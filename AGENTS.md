# Інструкції для роботи з Rodovid

Працюй українською. Перед змінами перевір стан Git і збережи наявні правки.

## Перевірені матеріали власника

Власник додає тільки перевірені відомості й матеріали (уточнення 28.10.2026).
Окреме оцінювання доказів і повторна перевірка заради заповнення технічних
оцінок не потрібні. Не трактуй `confidence: unassessed` за замовчуванням
як неперевіреність доданих відомостей або незавершену задачу.
Зберігай джерела, оригінальні тексти, прив’язки та явні уточнення власника.

## Джерела та скани

Перед додаванням або імпортом джерел, сканів чи зміною їхніх прив’язок
прочитай [Docs/Adding_Event_Sources.md](Docs/Adding_Event_Sources.md).

- Один побайтово однаковий скан у робочих даних має один фізичний файл.
  Перед копіюванням порівняй його SHA-256 і байти з наявними сканами.
  За збігу використовуй наявний `media.path`.
- Не створюй копії зображення з іншою назвою для нового індексу FamilySearch,
  людини, події або JSON. Назви JSON і скану можуть відрізнятися.
  Кілька медіа-ID можуть посилатися на один файл, зберігаючи своє походження.
- Окремі індексні записи зберігають свої ID, URL, описи й доказові прив’язки.
  Однакове зображення або URL не доводить тотожність історичних актів.
- Для додавання використовуй `npm run source:add`. Нові імпортери й разові
  скрипти також мають повторно використовувати наявні файли. Заміна скану
  одного запису повинна зберігати спільне зображення інших записів.
- Після додавання або імпорту перевір `npm run source:sync`,
  `npm run source:dedupe` та `npm run data:validate`. Після застосування
  підготовлених змін повторна синхронізація має давати 0 створень,
  0 оновлень і 0 конфліктів; повторне прибирання — `removed: 0`;
  валідація — 0 помилок. Якщо лишилися копії, заверши їх прибирання
  через `npm run source:dedupe -- --apply` і повтори перевірки.

Під час прибирання зберігай відновлювану копію та відповідності старих
і нових шляхів. Оригінали сімейного архіву й історичні знімки не видаляй
у межах прибирання робочих даних сайту.
