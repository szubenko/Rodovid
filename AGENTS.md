# Інструкції для роботи з Rodovid

Працюй українською. Перед змінами перевір стан Git і збережи наявні правки.

## Порядок гілок нового вертикального родоводу

У діаграмі `/vertical-design/:personId` чоловіча (батьківська) гілка
розташована ліворуч, жіноча (материнська) — праворуч (правило власника
29.10.2026). Порядок визначай за записаною статтю та зберігай при зміні
центру, розгортанні братів/сестер, зміні щільності й експорті PNG.

Картки бокових людей поза основною предковою лінією мають 85% ширини
й висоти основних карток. Основна лінія — поточний центр та його прямі
предки; при зміні центру належність до неї перераховується. Масштабуй
усю композицію бокової картки та враховуй фактичні розміри в розкладці.
Великі й зменшені картки одного покоління вирівнюй по верхньому краю.

У жінок стрілка розгортання розташована праворуч від картки й у згорнутому
стані спрямована вправо. Нові картки її братів/сестер додаються праворуч;
повторне натискання згортає цю гілку. Дотримуйся напрямку в обох
щільностях і PNG, включно з неповнорідними братами/сестрами.

У чоловіків стрілка ліворуч і нові картки братів/сестер розгортаються
ліворуч від нього (уточнення 30.10.2026). Це правило зберігається
в обох щільностях, історії й PNG та для неповнорідних братів/сестер.

Верхня стрілка на картці згортає її предкову гілку, залишаючи саму
картку. Повторне натискання відновлює гілку та її бокові розгортання.
Показуй її тільки на основній кровній лінії — поточному центрі та
його прямих предках; на зменшених бокових картках її немає
(уточнення власника 30.10.2026). При зміні центру правило перераховується.
Напрямок верхнього шеврона інвертований за наступним уточненням:
на розгорнутій гілці він спрямований вниз, на згорнутій — вгору.
Бокова й верхня стрілки незалежні: відкриття братів/сестер не розгортає
предків. Згортання предків залишає власних відкритих братів/сестер;
бокова стрілка змінює тільки їхній стан (уточнення 30.10.2026).
Незалежні й вкладені згортання зберігаються через історію; спільного
предка, який потрібен іншій відкритій гілці, не приховуй разом із нею.

## Перевірені матеріали власника

Власник додає тільки перевірені відомості й матеріали (уточнення 28.10.2026).
Окреме оцінювання доказів і повторна перевірка заради заповнення технічних
оцінок не потрібні. Не трактуй `confidence: unassessed` за замовчуванням
як неперевіреність доданих відомостей або незавершену задачу.
Зберігай джерела, оригінальні тексти, прив’язки та явні уточнення власника.

## Джерела та скани

Перед додаванням або імпортом джерел, сканів чи зміною їхніх прив’язок
прочитай [Docs/Adding_Event_Sources.md](Docs/Adding_Event_Sources.md).

- Один побайтово однаковий скан у робочих даних має один фізичний файл.
  Перед копіюванням порівняй його SHA-256 і байти з наявними сканами.
  За збігу використовуй наявний `media.path`.
- Не створюй копії зображення з іншою назвою для нового індексу FamilySearch,
  людини, події або JSON. Назви JSON і скану можуть відрізнятися.
  Кілька медіа-ID можуть посилатися на один файл, зберігаючи своє походження.
- Окремі індексні записи зберігають свої ID, URL, описи й доказові прив’язки.
  Однакове зображення або URL не доводить тотожність історичних актів.
- Для додавання використовуй `npm run source:add`. Нові імпортери й разові
  скрипти також мають повторно використовувати наявні файли. Заміна скану
  одного запису повинна зберігати спільне зображення інших записів.
- Після додавання або імпорту перевір `npm run source:sync`,
  `npm run source:dedupe` та `npm run data:validate`. Після застосування
  підготовлених змін повторна синхронізація має давати 0 створень,
  0 оновлень і 0 конфліктів; повторне прибирання — `removed: 0`;
  валідація — 0 помилок. Якщо лишилися копії, заверши їх прибирання
  через `npm run source:dedupe -- --apply` і повтори перевірки.

Під час прибирання зберігай відновлювану копію та відповідності старих
і нових шляхів. Оригінали сімейного архіву й історичні знімки не видаляй
у межах прибирання робочих даних сайту.
