# Як додавати джерела до подій

Додавання виконується локально в папці проєкту. Сайт залишається
переглядачем: форм редагування чи завантаження файлів на ньому немає.

## Найпростіше — майстер у терміналі

Підготуйте скриншот JPG/PNG або PDF та текстовий файл TXT у UTF-8
з описом чи розшифровкою запису. Файли можуть лежати у вашому архіві;
скан буде скопійований, оригінал залишиться на місці.

Відкрийте PowerShell у папці сайту й запустіть:

```powershell
cd E:\PETprojects\Rodovid
npm run source:add
```

Майстер послідовно запитає:

1. Ім’я людини або її FamilySearch ID, наприклад `Наталия` чи `PFFS-2YZ`.
2. Номер людини та потрібної події зі списку. Тут є також народження дітей.
3. Додати нове джерело чи доповнити одне з наявних. Для чотирьох джерел
   Наталії вибирайте **наявне джерело** відповідної події.
4. Коротку назву латиницею, наприклад `natalia-birth-1894`.
5. Назву джерела та зовнішнє посилання. Enter зберігає наявне значення.
6. Шлях до TXT з текстом запису та шлях до JPG/PNG/PDF. Enter пропускає поле.

Дата й тип беруться з вибраної події. Майстер додає матеріали до неї;
якщо потрібно виправити саму дату чи учасників, це окрема правка родоводу.

Після перевірки команда збереже матеріали. У «Джерелі» буде видно
клікабельне посилання, «Опис» і скан без окремого підпису; зображення можна
відкрити в повному розмірі. Поля без матеріалів мають відповідну позначку.
Нерозбірливий текст позначайте `[нерозбірливо]`, власний переказ — як опис;
бібліографічне посилання не замінює розшифровку.

Локальний dev-сервер оновить сторінку після зміни даних. Для оновлення
опублікованої версії потрібна звичайна збірка й публікація сайту.

## Додавання через файл

Цей варіант підходить, якщо зручніше зберігати опис джерела поруч зі сканом
й повторно запускати одну команду. Список подій та їхніх ID:

```powershell
npm run source:list -- "Наталия"
```

Створіть `source.json` поруч із `description.txt` та `scan.jpg`:

```json
{
  "id": "natalia-birth-1894",
  "eventId": "event-836c7d8b122ca60e05653546",
  "sourceId": "source-0c2700dfad0a6f8a580a97f2",
  "url": "https://www.familysearch.org/ark:/61903/1:1:6X32-NT61",
  "descriptionFile": "description.txt",
  "screenshot": "scan.jpg"
}
```

Це готове зіставлення **народження Наталії 12.10.1894** з його наявним
джерелом. Для іншої події скопіюйте ID зі списку. Для нового документа
приберіть `sourceId` і додайте `title`. За потреби можна додати
`recordNumber` (номер запису) та `folio` (аркуш).
Замість `descriptionFile` дозволене поле `description` із текстом.
Відносні шляхи рахуються від папки `source.json`; абсолютні також працюють.

Перевірте без запису, потім застосуйте:

```powershell
npm run source:add -- --input "E:/RodovidZubenko/SelectedBooks/папка/source.json"
npm run source:add -- --input "E:/RodovidZubenko/SelectedBooks/папка/source.json" --apply
```

Не змінюйте `id` для повторного запуску того самого запису. Повторний
імпорт того самого файла не створює зайвих джерел або цитувань.
Оновлений текст замінює попередній; інший скан додається до цього джерела,
попередні скани зберігаються. Один документ можна прив’язати до кількох
подій, повторно використавши його `sourceId` та окремий `id` для прив’язки.

## Зберігання й відновлення

Команда доповнює `Data/annotations.json`, а файли копіює в
`Data/assets/documents/source-records/`. Наявні джерела та цитування
доповнюються зі збереженням ID і походження. Нове джерело має ID
`source-record-<id>`.

Перед кожним записом створюється копія попереднього `annotations.json`
у `tmp/source-records/`; точний шлях друкується в результаті команди.
Для скасування відновіть цю копію в `Data/annotations.json`.
Файли без прив’язок не включаються до збірки.

GEDCOM, база RootsMagic, журнал ідентичностей та оригінали архіву
не змінюються. Після повторного експорту інструмент перевірки повідомить
про зниклі цілі доповнень; такі прив’язки потрібно явно зіставити.
