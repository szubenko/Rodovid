# Як додавати джерела до подій

Кожен запис — це пара файлів з однаковою основою назви:

```text
заприса-наталія-народження-PFFS-2YZ-6X32-NT61.png
заприса-наталія-народження-PFFS-2YZ-6X32-NT61.json
```

Порядок частин: **прізвище-ім’я-типподії-IDлюдини-IDджерела**.
Імена й тип події — малими літерами, FamilySearch ID — у вихідному
написанні. `PFFS-2YZ` позначає людину, `6X32-NT61` — індексований запис
джерела. Для народження дитини використовуємо ім’я та ID дитини.
Для шлюбу — одного з учасників, до чиєї події додаємо документ.

Типи подій у назвах: `народження`, `шлюб`, `смерть`, `хрещення`,
`поховання`, `проживання`, `інша-подія`. Ім’я в назві допомагає орієнтуватися;
зіставлення людини виконується за FamilySearch ID.

## Вміст JSON

JSON має рівно два поля, зберігається у UTF-8:

```json
{
  "url": "https://www.familysearch.org/ark:/61903/1:1:6X32-NT61",
  "description": "Розпізнаний текст метричного запису.\nНаступний рядок."
}
```

`url` відображається як «Зовнішнє посилання», `description` — як «Опис».
Перенесення рядка всередині JSON-рядка записується як `\n`.
Якщо розшифровка ще не готова, дозволено `"description": ""`.
Непевні місця позначайте `[нерозбірливо]`, власний переказ — як опис.
Бібліографічний опис або індекс FamilySearch не замінює розшифровку скану.

Зображення знаходиться поруч за тією самою назвою. Основний формат — PNG;
JPG/JPEG та PDF також підтримуються зі збереженням свого розширення.
Поруч із JSON повинен бути один скан із відповідною основою назви.

## Додавання готової пари

Підготуйте обидва файли в зручній папці архіву. У PowerShell:

```powershell
cd E:\PETprojects\Rodovid
npm run source:add -- --input "E:/RodovidZubenko/SelectedBooks/папка/заприса-наталія-народження-PFFS-2YZ-6X32-NT61.json"
```

Ця команда перевіряє пару без запису. Для збереження додайте `--apply`:

```powershell
npm run source:add -- --input "E:/RodovidZubenko/SelectedBooks/папка/заприса-наталія-народження-PFFS-2YZ-6X32-NT61.json" --apply
```

Команда знайде людину й наявне джерело за двома ID у назві, вибере подію,
скопіює PNG і JSON у `Data/assets/documents/source-records/` та збереже
прив’язку. Для нового запису джерела створить окреме джерело. Повторне
додавання тієї самої пари оновлює її без дублювання цитувань.
Якщо кілька подій підходять і джерело ще не визначає одну з них,
потрібно вибрати точну подію через локальний майстер.

## Локальний майстер

Якщо файли ще мають довільні назви:

```powershell
npm run source:add
```

Майстер запропонує знайти людину за ім’ям або FamilySearch ID,
вибрати подію та наявне джерело або додати нове. Далі вкажіть посилання,
опис (або JSON із двома полями) та шлях до скану. Назви обох вихідних
файлів сформуються автоматично за погодженою схемою.

Події людини можна переглянути окремо:

```powershell
npm run source:list -- "Наталия"
```

## Подальше редагування

Після першого додавання відкривайте JSON безпосередньо в
`E:/PETprojects/Rodovid/Data/assets/documents/source-records/`.
Опис і посилання беруться саме з цього файла при перевірці та збірці;
окрема редагована копія опису в `annotations.json` не створюється.
Увімкнений локальний dev-сервер оновить сторінку після зміни JSON або скану.
Для оновлення опублікованого сайту потрібна звичайна збірка й публікація.

Якщо редагуєте копію пари поза папкою сайту, повторіть імпорт із `--apply`.
Не перейменовуйте вже прив’язану пару вручну: її шляхи записані в
`Data/annotations.json`. Відсутній чи некоректний JSON або скан зупинить
підготовку даних із повідомленням про помилку.

Перед записом майстер зберігає попередні доповнення й замінювані файли
в `tmp/source-records/`; точний шлях друкується в результаті команди.
Для відновлення використайте цю копію доповнень і файлів. GEDCOM,
RootsMagic, журнал ідентичностей та оригінали архіву не змінюються.

JSON потрібен для локальної підготовки. У збірку сайту включаються
підготовлений опис, посилання та прив’язане зображення; сторонні файли
з папки архіву автоматично не публікуються.
