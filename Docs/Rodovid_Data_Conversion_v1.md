# Перетворення даних Rodovid v1

ROD-005, 2026-09-09. Команда виконується локально в Node.js 24.18.0:

```sh
npm run data:convert
```

Вхід — `Data/Zubenko.ged`, `Data/site.json`, `Data/annotations.json` і
[`Data/identities.json`](../Data/identities.json). Вихід — `generated/family.json`
за [контрактом v1](Rodovid_Data_Contract_v1.md) та `tmp/data-conversion.json`.
Обидва результати виключені з Git; журнал ID і доповнення зберігаються у Git.
Сайт поки не завантажує JSON: інтеграція зі статичною збіркою належить ROD-007.

Відносні аргументи рахуються від кореня репозиторію, незалежно від поточної
папки термінала. Доступні `--gedcom`, `--config`, `--supplements`,
`--identities`, `--out`, `--report`, `--assets-root`, `--validate-only`. Для нового незалежного набору, якому ще
не створено журнал, потрібне явне `--init-identities`:

```sh
npm run data:convert -- --gedcom tmp/example.ged --config tmp/site.json --supplements tmp/annotations.json --identities tmp/identities.json --out tmp/family.json --report tmp/report.json --init-identities
```

Прапорець відмовляється перезаписувати наявний журнал. Не застосовуйте його
до повторного експорту замість зіставлення. Звичайний запуск читає журнал
без змін. За помилки команда повертає код 1 і діагностику в stderr;
перевірки входу виконуються до запису family.json. Попередній JSON
залишається на диску після невдалого запуску — він не є результатом
нового входу. ROD-006 записує звіт помилки, якщо шлях звіту доступний.
Перевіряйте код завершення та статус `validation` у звіті. Запис кожного
вихідного JSON виконується через тимчасовий файл і перейменування.

## Журнал і повторні експорти

Конвертер шукає рівно один запис `imports` із SHA-256 фактичних байтів GEDCOM.
Для базового експорту це `02a5e903ed7e261e58b5866d01fde1af16867c2594a23480c21c4ef6d4fb4fdd`.
`.gitattributes` фіксує оригінальні CRLF цього файла при checkout на різних
платформах. Після іншого експорту перевірте також його закінчення рядків:
будь-яка зміна байтів потребує нового запису імпорту. Для експорту з іншими
закінченнями рядків слід узгодити правило Git до обчислення контрольної суми.

Перший імпорт призначає людям ID з XREF (`@I1@ → I1`). Решта ID мають
префікс типу та 24 шістнадцяткові символи, обчислені від початкового locator.
Це лише початкове присвоєння: після збереження журналу ID беруться **тільки
з явного зіставлення**, а не повторно обчислюються з нового файла.

1. Збережіть попередній журнал; зареєструйте новий `importId` і фактичний SHA-256.
2. Додайте до відповідних `entries[].origins` нові `recordId` і `path`.
   Не змінюйте канонічний `entity.id`. Наприклад, новий `@I42@` може
   відповідати старому `I1`, але це треба вказати явно.
3. Зіставте також сім’ї, зв’язки, події, твердження, місця, джерела й цитування.
   Перестановка народжень `BIRT[0] ↔ BIRT[1]` потребує нових шляхів для
   вкладених дат, місць і цитувань. Збіг імен не використовується.
4. Новій сутності призначте новий невикористаний ID; для вилученої не додавайте
   походження нового імпорту. Старі походження залишаються в журналі.
5. Запустіть конвертер. Відсутнє чи зайве зіставлення поточного імпорту,
   невідома ціль доповнення або налаштування зупиняють перетворення.

Шляхи тегів мають нульові індекси серед однакових тегів: `BIRT[0].DATE[0]`.
Для зв’язку locator об’єднує два шляхи сімейних ролей, наприклад
`HUSB[0]+CHIL[0]`; у `provenance` збережені обидва точні вихідні шляхи.
Для цитування locator має суфікс типу й канонічного ID цілі, оскільки одна
сімейна цитата може стосуватися кількох зв’язків. До журналу додано тип
`evidenceLink`; наявні журнали контракту v1 залишаються сумісними.

## Що перетворюється

- Люди, усі варіанти `NAME`, складові імен, FamilySearch і RootsMagic UID.
  Ім’я зберігає `raw`; `display` прибирає GEDCOM-роздільники прізвища.
  Основний варіант і достовірність не визначаються порядком записів.
- Сирі сім’ї зберігаються у звіті й журналі. Кожне поєднання явних
  `HUSB/WIFE` і `CHIL` створює окремий зв’язок; сам шлюб не створює дітей.
  Зворотні `FAMC/FAMS` перевіряються, але не додають нових батьків.
- Народження, смерть, шлюб, хрещення, поховання, проживання та інші
  стандартні події/підтримані атрибути. Неспеціалізований тип зберігає тег
  або `TYPE` як назву. Повторні події не зливаються. Дата, місце, причина
  й опис події залишаються окремими твердженнями.
- Рік, місяць, повна дата, `ABT/EST/CAL/BEF/AFT`, `BET … AND …`,
  `FROM … TO …` та відкриті періоди. Підтримані явні григоріанський і
  юліанський календарі перед датою без перерахунку. Без явного календаря
  контракт зберігає `unspecified`. Подвійні роки, дати до н.е., `INT`,
  непідтримані календарі/форми залишаються `phrase` з оригіналом і попередженням.
- Входження `PLAC` мають окремі стабільні ID навіть за однакового тексту.
  Нормалізація назви та координати додаються лише через `placeEnrichments`.
- Вбудовані й спільні `NOTE`, зокрема `CONT/CONC`, стають описами або
  поясненнями; спільна нотатка зберігає додаткове походження. Цикл NOTE — помилка.
  Нотатки не перетворюються автоматично на авторські спогади.
- Записи `SOUR`, основна бібліографія, вбудовані цитування, `PAGE`,
  `DATA.TEXT`, примітки та сирий `QUAY`. `PAGE` зберігається текстом у
  поясненні: довільний архівний locator не видається за номер сторінки PDF.
  `QUAY` не підвищує `confidence`. Заголовок `SOUR RootsMagic` не є доказом.
- Доповнення додають альтернативні твердження з причиною, явний основний
  варіант, оцінки, пояснення, джерела, медіа, фрагменти доказів, спогади
  й відомості про місця. Кожне застосування додає походження доповнення;
  пояснення оцінки зберігається разом із вихідною приміткою.

Розбір основних форм звірено зі [специфікацією GEDCOM 5.5.1](https://gedcom.io/specifications/ged551.pdf),
зокрема структурами подій, сімей, нотаток і цитувань та `DATE_VALUE`.
Це підтримка описаної підмножини, а не декларація повної сумісності GEDCOM.

## Базовий результат та межі

| Показник | Значення |
| --- | ---: |
| Люди / домашня особа | 25 / I1 |
| Сирі сім’ї / прив’язки дітей | 9 / 32 |
| Зв’язки | 71: 8 подружніх і 63 батьки–діти |
| Події | 48: 22 народження, 22 смерті, 4 шлюби |
| Твердження | 77 |
| Входження місць / різні вихідні тексти | 24 / 8 |
| Джерела / медіа / докази / спогади | 0 / 0 / 0 / 0 |

Жодну сім’ю або подію не злито. Відсутні координати й фото залишаються
відсутніми. Життєвий статус без явного свідчення смерті — `unknown`,
а не `alive`. GEDCOM і RootsMagic не змінені.

[`Data/annotations.json`](../Data/annotations.json) переносить правила
[реєстру D01–D06](Rodovid_Data_Decisions_2026-09-09.md): 62 записи пояснень
до зв’язків/тверджень і 24 пояснення до входжень місць. Усі оцінки —
`unassessed`, проблемні зв’язки — `unreviewed`. Історичні рішення залишаються
за власником; ці доповнення не додають альтернативного виправленого імені,
доказів, координат або нових генеалогічних фактів.

Звіт містить контрольну суму, кількості, сирі сім’ї, попередження про
чотири входження можливих дублів, застосовані пояснення D01–D06 та кожен
неперетворений вузол із XREF, шляхом, рядком і значенням. У базовому
наборі це 25 тегів `SEX`, для яких поточний контракт не має поля.
Метадані `HEAD/CHAN/_EVDEF/TRLR` не стають подіями або доказами.

GEDCOM-медіаструктури `OBJE/FILE`, репозиторії `REPO`, непідтримані
розширення та деталі структур залишаються у звіті, а не копіюються
автоматично. Для матеріалів поточного конвертера використовуйте явні
підготовлені `Media/Source/EvidenceLink` у доповненнях. Наявність таких
неперетворених структур потребує розгляду до використання нового набору.

Перевірки конвертера відхиляють колізії ID, невідомі цілі, конфліктні
оцінки/основні варіанти та фрагменти чужого джерела.
[ROD-006](Rodovid_Data_Validation_v1.md) додає діагностику графа,
календарних меж, наявності й сигнатур файлів та блокування підготовки/збірки
за непідтриманих структур. Звіт тепер містить розділ `validation`
і читабельний супровід `.json.md`; JSON записується лише після успішної перевірки.
Копіювання даних і матеріалів до статичної збірки належить ROD-007.

Перевірки: `npm test` (реальний набір, складний синтетичний GEDCOM,
зміна XREF і порядку вкладених подій, CLI та негативні сценарії),
`npm run lint`, `npm run build`, `npm run data:check-gedcom`.
