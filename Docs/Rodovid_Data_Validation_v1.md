# Валідація підготовки Rodovid v1

**Дата:** 2026-09-09. **Тікет:** [ROD-006](tickets/006-data-validation.md).

## Запуск і результат

```sh
npm run data:validate
npm run data:convert
npm run build
```

`data:validate` заново читає GEDCOM, налаштування, доповнення й журнал ID,
перетворює їх у пам’яті та перевіряє результат. Команда не змінює журнал ID
чи `generated/family.json`. `data:convert` виконує ті самі перевірки і записує
JSON лише після успіху. `build` спочатку запускає `data:validate`; код 1
зупиняє команду до TypeScript/Vite. Копіювання JSON і матеріалів до `dist/`
залишається обсягом ROD-007.

Обидві команди зберігають машинний звіт `tmp/data-conversion.json`
і читабельний `tmp/data-conversion.json.md`. Параметр `--report` змінює
шлях JSON; до цього шляху додається `.md` для текстового звіту.
Звіт містить статус, кількості, діагностику з рівнями `error/warning/info`,
канонічні ID, вихідні XREF, шляхи тегів і рядки, де вони доступні.
Повний звіт конвертера також зберігає SHA-256, сирі сім’ї, значення
непідтриманих тегів і застосовані пояснення.

Помилка читання, JSON, схеми, парсера, ID або доповнення до завершення
конвертації записується як `PREPARATION_FAILED` з вихідним повідомленням;
кількості ще не побудованого набору не вигадуються. Після виправлення
потрібен повторний запуск. Помилка не перезаписує попередній JSON і не
створює журнал для невдалого першого імпорту. Некоректні аргументи CLI,
колізія шляхів чи недоступний шлях звіту можуть залишити лише stderr і код 1.

Функція [`validateData`](../scripts/validation/validate.ts) приймає також
довільний JSON: спочатку Zod-схема, потім посилання, граф, дати й файли.
Відомості про сирі сім’ї, непідтримані теги та винятки ROD-004 беруться
зі звіту конвертера. Тому самостійна перевірка JSON без цього звіту
не замінює повну команду підготовки з GEDCOM.

## Що зупиняє підготовку

| Умова | Діагностика / правило |
| --- | --- |
| Некоректна схема | `INVALID_SCHEMA`; шлях поля та помилка Zod. |
| Дубль ID у колекції, невідома ціль, домашня особа, медіа кімнати/аудіо, конфлікт основних тверджень | `INVALID_REFERENCE_OR_ID` або рання помилка конвертера. Перевіряються також джерела, фрагменти доказів, події та спогади. |
| Неприв’язане доповнення, конфлікт оцінок, невідповідний імпорт/журнал ID | Рання помилка конвертера; нічого не відкидається мовчки. |
| Цикл батьківства | `ANCESTRY_CYCLE`; усі ребра циклів та їхні сімейні XREF. |
| Нові суперечливі ролі чи однаковий склад сімей | `CONFLICTING_ROLES`, `POSSIBLE_DUPLICATE_FAMILY`; потрібен ручний розгляд. Порядок дітей не приховує дубль. |
| Повторне посилання на ту саму роль або кілька HUSB/WIFE в одній сім’ї | `CONFLICTING_FAMILY_ROLE`; сценарій не підтримується автоматично. |
| Непідтримана структура | `UNSUPPORTED_STRUCTURE`; нові теги, OBJE/FILE, REPO й невикористані деталі джерел блокують втрату відомостей. |
| Втрата базових записів або пояснень D01–D06 | `BASELINE_COUNT_MISMATCH`, `BASELINE_DATA_LOSS`, `REVIEW_POLICY_MISSING`. |
| Неможливий день або зворотний інтервал | `INVALID_CALENDAR_DATE`, `REVERSED_DATE_RANGE`. |
| Відсутній, непрочитуваний, порожній, невідповідний оголошений файл | `INVALID_DECLARED_FILE`; ID медіа й шлях. |
| PDF/аудіо замість фото або фону, неаудіо у звукових налаштуваннях, невідповідний медіафрагмент | `INVALID_MEDIA_ROLE`; сторінка PDF й область зображення потребують явного файла відповідного типу. |
| Основний портрет не входить до фото людини | `PORTRAIT_NOT_IN_PHOTOS`. |

Обхід графа використовує відвідані `personId` та закінчується за циклів
і повторів. Повторний предок через різні гілки сам по собі дозволений.
Паралельні записи зв’язку мають інформаційний `REPEATED_RELATIONSHIP`;
вони не зливаються й не збільшують достовірність.

Єдиний дозволений неперетворений предметний тег — безпосередній `INDI.SEX`:
контракт v1 не використовує це поле, тому `UNMAPPED_SEX` є попередженням,
а його значення зберігається в JSON-звіті. Невідомі дочірні теги SEX
залишаються помилками. Відомі шляхи метаданих HEAD/CHAN/_EVDEF/TRLR
перераховані в конвертері; невідомі нащадки цих структур також перевіряються.

Нерозібрана дата збережена дослівно й має `UNPARSED_DATE`; це не втрата
відомостей. Перевірка відомих календарів не конвертує дати. Для `unspecified`
29 лютого столітнього року не відкидається, якщо він можливий за юліанським
календарем. Межі року/місяця використовуються лише для перевірки інтервалу,
у дані не додається вигаданий день. Рік народження 1917 і смерть 23.01.1917
не трактуються як доведена смерть до народження.

## Матеріали

За замовчуванням `Media.path = assets/documents/example.pdf` перевіряється
як `Data/assets/documents/example.pdf`. Для окремого набору:

```sh
npm run data:validate -- --assets-root path/to/content
```

Перевіряються всі оголошені медіа, навіть ще не використані у кімнаті:
існування, звичайний файл, читання й сигнатура JPEG/PNG/PDF/MP3/Ogg/WAV.
Реальний шлях не може виходити за папку матеріалів через символічні
посилання. Сигнатура — базова перевірка типу, а не повне декодування чи
оцінка читабельності скану; підготовка матеріалів і візуальний перегляд
належать наступним тікетам.

Якщо фото, джерела, спогади або координати взагалі не оголошені,
це допустимий порожній стан (`OPTIONAL_CONTENT`). Папка матеріалів
за відсутності медіа не потрібна. Оголошений відсутній файл є помилкою.

## Базовий набір і невирішені питання

Для SHA-256 базового GEDCOM з [огляду](Rodovid_Data_Review_2026-09-09.md)
перевірено: **25 людей, 9 сирих сімей, 32 прив’язки дітей, 71 зв’язок,
48 подій, 77 тверджень, 24 входження місць; джерел/медіа/доказів/спогадів — 0**.
Сирі лічильники включають 22 народження, 22 смерті, 4 шлюби та 65 визначень
типів подій, які не стають подіями життя.

Результат: **0 помилок, 34 попередження, 29 інформаційних повідомлень**.
Попередження: шість D01–D06, два можливі дублікати F6/F7 і F8/F9,
суперечливі ролі F3/F5 та 25 тегів SEX. Усі D01–D06 залишаються
«Не з’ясовано»; відповідальний — власник родоводу.

Дозволи для прототипу спираються на [реєстр ROD-004](Rodovid_Data_Decisions_2026-09-09.md)
і застосовуються лише до його точного експорту. Обов’язкові пояснення
перевіряються на конкретних зв’язках/твердженнях/місцях; оцінки залишаються
`unassessed`, проблемні зв’язки — `unreviewed`. Втрата пояснень або
підвищення цих оцінок без оновлення правил зупиняє підготовку.
Новий експорт не успадковує винятки лише через збіг XREF: після ручного
розгляду потрібно узгоджено оновити реєстр, доповнення й правила перевірки.
Прапорця вимкнення помилок немає.

Проходження перевірки підтверджує технічну цілісність підготовки.
Історична правильність, точні підписи спорідненості через проблемні ребра
та достовірність FamilySearch не встановлюються автоматично.

## Виконані перевірки

`npm test` — 138 тестів, включно з реальним набором та негативними CLI-сценаріями:
втрачений ID, невідома домашня особа, неприв’язане доповнення, відсутній файл,
цикл, дубль сім’ї та невідомий тег. Перевірено код 1, JSON/Markdown-діагностику,
збереження попереднього результату й відсутність журналу невдалого імпорту.
Окремо перевірено повторних предків, календарі, сигнатури й невідомі теги
всередині метаданих. Також виконано lint, типи, збірку, базову GEDCOM-звірку
та детермінований повтор підготовки. Вихідні GEDCOM/RootsMagic незмінені.
