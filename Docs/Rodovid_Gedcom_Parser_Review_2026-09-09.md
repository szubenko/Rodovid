# Перевірка парсера GEDCOM — ROD-003

**Дата:** 2026-09-09. **Рішення:** `read-gedcom 0.3.2` придатний для
читання наданого RootsMagic GEDCOM 5.5.1 через адаптер сирого дерева.
Відомості базового експорту не втрачені; перехід на GEDCOM 7 не потрібний.

Версію звірено через `npm view read-gedcom version repository engines --json`
та зафіксовано в `devDependencies` і lockfile. Автор описує орієнтацію на
GEDCOM 5.5.5 зі зворотною сумісністю; висновок для нашого 5.5.1 спирається
на локальну перевірку конкретного файла. Джерела:
[репозиторій автора](https://github.com/arbre-app/read-gedcom),
[API parseGedcom](https://docs.arbre.app/read-gedcom/modules/Parsing.html).

## Відтворення

У корені репозиторію після `npm ci`:

```sh
npm run data:check-gedcom
npm test
npm run lint
npm run build
```

Команда `data:check-gedcom` читає `Data/Zubenko.ged`, перевіряє
контрольну суму, усі рядки, кількості та цілі сімейних посилань. Помилка
дає ненульовий код виходу. Вона створює локальний `tmp/gedcom-probe.json`
із контрольними результатами та повним переліком розширень і непідтриманих
вузлів. Звіт відтворюється командою, виключений із Git і не входить у сайт.
Після невдалого запуску попередній звіт не підтверджує новий експорт:
перевіряйте код виходу та SHA-256.

Це звірка **незміненого базового експорту**. Після нового експорту чи
погоджених виправлень вона навмисно завершується помилкою контрольної суми;
нову базу потрібно окремо переглянути, а не підганяти до старих кількостей.

## Адаптер і межі підтримки

[`scripts/gedcom/parse.ts`](../scripts/gedcom/parse.ts) викликає `parseGedcom`
із `noIndex`, `noInlineContinuations` і `doFreeze`. У Node передається копія
саме вхідного зрізу байтів, щоб не прочитати зайві байти з пулу Buffer.
Повне дерево з порядком вузлів, сирими значеннями та номерами рядків
залишається доступним. Масиви не згортаються до одного значення й не
дедуплікуються. Це проміжне представлення для перевірки, а не JSON за
[контрактом сайту](Rodovid_Data_Contract_v1.md).

| Конструкція | Обробка в ROD-003 |
| --- | --- |
| INDI, NAME/GIVN/SURN, SEX, FAMC/FAMS | Сирі ID, масиви імен, статі й посилань; повне дерево |
| FAM, HUSB/WIFE/CHIL | Усі ролі, порядок і повтори |
| INDI.BIRT/DEAT, FAM.MARR | Події тільки у відповідному записі; значення, всі DATE/PLAC, рядок походження |
| `_FSFTID` × 25, `_UID` × 25 | Явні сирі поля; FamilySearch ID не стає історичним доказом |
| `_EVDEF` × 65 | Службове піддерево визначень типів, не подія життя |
| HEAD, CHAN, TRLR | Службові дані збережені; HEAD.SOUR RootsMagic не стає джерелом факту |
| Інші теги / розширення | Збережені в дереві; поза службовими піддеревами включені в `unhandledNodes` з шляхом, ID, рядком і значенням |
| CONT/CONC | Збережені окремими вузлами; складання тексту належить перетворювачу |

Обмеження:

- Висновок стосується цього експорту та синтетичних перевірок, не всіх
  GEDCOM. Повну відповідність стандарту й інші кодування не доведено.
- Дати поки сирі: приблизність, діапазони та календарні позначки не
  перетворюються на JavaScript Date. Зіставлення з HistoricalDate реалізує
  ROD-005; відсутність дати смерті не визначає життєвий статус.
- Інші типи подій, джерела, QUAY, медіа та нотатки зберігаються, але ще не
  перетворюються на сутності сайту. `unhandledNodes` означає відсутність
  предметного зіставлення, а не втрату парсером або помилку GEDCOM.
- Службові піддерева зберігаються без предметної інтерпретації дочірніх
  тегів. Усі теги з `_` додатково потрапляють до `extensions`.
- Перевірка синтаксису бібліотекою не замінює майбутню валідацію графа,
  цитувань і медіапосилань. D01–D06 залишаються для ROD-004.

## Автоматичні перевірки

[`parse.test.ts`](../scripts/gedcom/parse.test.ts) містить 12 перевірок:
реальний експорт, дублікати, конфліктні ролі, неповні дати, службові теги,
відхилення зміненої бази й виявлення втрати сирого поля. Повністю синтетичний
приклад перевіряє альтернативні імена й народження, повторний CHIL,
ABT/BET/FROM і календарний escape, SOUR/QUAY/OBJE, невідоме розширення,
CONT/CONC, LF/CRLF, BOM, зріз Buffer та відмову на пошкодженому вводі.

Пройшли: команда звірки, **53 тести загалом**, TypeScript, ESLint і статична
збірка. Браузерний інтерфейс не змінювався. Парсер працює лише в Node;
сімейний GEDCOM, RootsMagic і звіт не додаються в `dist/`.
