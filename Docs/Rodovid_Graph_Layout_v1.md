# Проєкція графа й секторна геометрія — ROD-010

Оновлено: 2026-09-13.

## Використання

`src/graph/projection.ts` і `src/graph/layout.ts` — чисті TypeScript-функції без
React, DOM, мережевих запитів або зміни вхідних даних. Повний граф індексують
один раз після завантаження, проєкцію обчислюють для поточного центру та
параметрів `ViewState.current.map`.

```ts
const graph = buildFamilyGraph(family)
const projection = projectFamily(graph, current.centerPersonId, {
  generations: current.map.generations,
  collapsedAppearanceIds: current.map.collapsedAppearanceIds,
})
const layout = layoutRadial(projection, {
  width: 320, height: 320,
  labels: new Map(family.people.map((person) => [person.id, personName(family, person.id)])),
})
```

`personName` уже розв’язує основний варіант імені або перший наявний запис,
коли `isPrimary` не вказано. Повне ім’я залишається у `fullLabel`, навіть якщо
дуговий підпис скорочений. Генерований JSON не отримує екранних координат.

## Граф, повтори та навігація

- `buildFamilyGraph` зберігає кожен `relationshipId`, обидва кінці, походження,
  оцінку та пояснення. Дублікати ID й відсутні кінці спричиняють явну помилку.
  Індекси надаються як readonly; сутності належать незмінному набору даних.
- `appearanceId` описує шлях від центру через напрям і конкретні ID зв’язків.
  Довжини частин включені в ключ, тому крапки, двокрапки й дефіси в ID не
  створюють колізій. Глибина, розмір екрана й згортання не входять у ключ.
  Кімнату завжди відкривають за `personId`.
- Порядок сусідів визначають канонічний `personId`, потім `relationshipId`,
  порівнянням кодових одиниць без залежності від локалі. Це порядок показу,
  а не твердження про вік, стать чи порядок народження. Перестановка вхідних
  масивів не пересуває гілки.
- Вгорі обходяться лише предки. Внизу — подружжя поточного центру та його
  нащадки; подружні ланцюжки не розгортаються автоматично. Бічна гілка
  доступна переходом до батька/матері та далі до іншої дитини.
- `edges` пов’язують екранні появи, зберігаючи вихідний напрям батько/мати →
  дитина й конкретний `relationshipId` для подальшого показу доказів.
- D01/D02 залишають окремі сектори та зв’язки. D03 залишає I6 біля I9 і як
  подружжя, і як дитину з різними зв’язками. Жодне з цих тверджень не стає
  історично підтвердженим унаслідок розкладки.

Цикл перевіряється за людьми тільки в поточному шляху. Поява, що замикає
цикл, залишається з `cycle: true`, але її продовження зупиняється. Повторний
предок в іншому шляху не забороняється. Обхід у ширину віддає перевагу близьким
родичам. Захисна межа — 2000 появ за замовчуванням, параметр 1–10000;
глибина 1–12. Некоректні значення відхиляються, а не округлюються мовчки.

`hiddenConnections` містить конкретну людину, зв’язок і причину: `depth`,
`collapsed`, `cycle`, `limit` або `recenter` (інший напрям, доступний після
зміни центру). Перевищення бюджету додатково встановлює `truncated: true`.
Згортання застосовується лише до вказаної появи; джерельний граф зберігається.

## Кільця та підписи

Композиція наслідує ROD-008: предки займають −108°…108°, нижня область —
116°…244°. Сектори предків і нащадків вкладені в кутовий проміжок попередньої
появи. Для предків резервуються щонайменше два місця; порожня частина
не створює вигаданої людини. Геометрія повертає тільки наявні появи.

Центр має `generation: 0`, предки — −1, −2 тощо, нащадки — +1, +2.
`ring` — окрема екранна величина: предки починаються з 1, подружжя має
кільце 1 і покоління 0, діти — кільце 2 і покоління +1. Три початкові
покоління означають центр і два кільця, як у погодженому прототипі;
вибір чотирьох поколінь додає прадідів та онуків. Це не оцінка спорідненості.

Розмір береться з меншої сторони області; координати повертаються у пікселях
цієї області без трансформації камери. Довжина підпису обмежена довжиною
дуги з відступами, центральне ім’я має до трьох рядків. Нижні дуги мають
ознаку зворотного напрямку тексту. Шрифт 12/14 px не зменшується автоматично:
за нестачі місця повертається скорочення або порожній дуговий підпис.
Консервативну оцінку ширини можна замінити `measureText` для реального шрифту.

На щільних гілках, особливо I20 з чотирма поколіннями й дублікатами сімей,
частина секторів надто вузька для тексту навіть на широкому екрані. Рендерер
ROD-011 має використовувати `fullLabel` у доступних назвах і списку людей;
ROD-013 додасть масштабування та згортання. Ця перевірка не означає, що
вузькі сектори вже мають придатні для дотику області або що аудит ROD-028 пройдено.

## Перевірено

22 нові Vitest-тести використовують свіжу конвертацію справжнього GEDCOM і
окремі синтетичні графи. Початкова I1 має 5 появ; усі 25 людей досяжні тільки
через видимі появи зі зміною центру; всі 71 зв’язок доступні. Перевірено
повторного предка, цикли, дублікати сімей, кілька подружніх зв’язків, неповні
сім’ї, глибину, згортання, бюджет, стабільні ID й порядок. Геометрія всіх 25
центрів перевірена на 320/1024 px за глибини 1, 3, 4, 12: скінченні координати,
межі області, відсутність перекриття секторів одного кільця, ширина підписів.

Для відтворення візуальної перевірки:

```sh
npm run data:convert
node scripts/review-graph.ts
```

Команда створює локальні HTML, PNG і `report.json` у `tmp/rod010/`. Шість
знімків I1/3, I9/3, I20/4 на 320 і 1024 px переглянуто; браузер перевірив
фактичну довжину SVG-тексту — жодного виходу за відведену ширину. Скрипт
огляду не входить у застосунок або статичну збірку.

Повний набір: 176 модульних тестів і 20 браузерних сценаріїв, типи, lint та
збірка пройшли. `tsconfig.node.json` явно включає DOM для браузерних
`evaluate`-callback у Playwright. Дані, залежності та UI застосунку незмінені.
