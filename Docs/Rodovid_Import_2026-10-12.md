## Підтримка експорту

Конвертер читає NAME.ROMN, імена без окремих GIVN/SURN, сімейні _UID та
примітки FAMC/FAMS з продовженнями CONT/CONC. Примітка про хронологію
відображається в кімнаті Иосифа й у відповідних родинних шляхах.
UID програми експорту відокремлено від FamilySearch ID.

10 повністю порожніх MARR збережено в діагностиці як контекст, що не встановлює
події шлюбу; імпортовано два шлюби з датами. 45 статусів DECEASED у перевіреній
копії перетворено на DEAT Y з приміткою, без вигаданих дат.

Вхід залишається нестандартним у деталях заголовка й ROMN: відсутність HEAD.SUBM
та ROMN.TYPE зафіксована у звіті архіву. Це не заважає контрольованому імпорту
сайту, але повна відповідність GEDCOM 5.5.1 не заявляється.

## Відтворення та перевірки

`node scripts/import-2026-10-12.mjs` готує кандидат у `tmp/import-2026-10-12/`.
`--source=<шлях>` задає перевірену копію; точний SHA-256 обов’язковий.
`--apply` записує робочі входи лише після валідації, якщо активний GEDCOM
збігається з попереднім або цим імпортом. Після цього `npm run data:convert`
відтворює JSON; `npm run build` і `npm run build:react-svg` створюють збірки.
