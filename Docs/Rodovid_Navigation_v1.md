# Маршрути та стан перегляду — ROD-009/012/013

Оновлено: 2026-09-13.

## Адреси й початок перегляду

| Адреса | Поведінка |
| --- | --- |
| `/` | Після завантаження даних замінює поточний запис історії на `/tree/I1`. Домашня особа береться з `config.homePersonId`. |
| `/tree/:personId` | Відкриває карту вказаної людини. |
| `/person/:personId` | Відкриває кімнату вказаної людини. |
| Невідомий ID / інша адреса | Показує повідомлення та доступну дію «До мене». |

ID відповідають контракту (`I1`, без GEDCOM-обгортки `@`). Прямі адреси й
перезавантаження перевірено через локальний Vite preview. Перезавантаження
залишає людину та екран з URL, повторно завантажує актуальний JSON і скидає
тимчасові параметри карти. Нове відвідування `/` починається з I1; пряме
посилання має пріоритет. Автоматичного відновлення останнього відвідування немає.

## Дані та помилки

`src/data/load-family.ts` завантажує `data/family.json` від базової адреси
застосунку. Один Promise спільний для всіх екранів і повторних підписок
React StrictMode. Після успіху дані залишаються в пам’яті вкладки; переходи
не роблять нових запитів. Запит використовує `cache: 'no-store'`.

У браузері перевіряються Zod-контракт, сімейний тип набору, унікальні ID людей,
наявність домашньої особи й кінці родинних зв’язків. Повну предметну перевірку
джерел, матеріалів та графа, як і раніше, виконує конвеєр ROD-006/007 перед збіркою.

Завантаження має текстовий статус. Мережева, HTTP-помилка, невалідний JSON чи
контракт показують зрозуміле повідомлення, кнопку повторної спроби й посилання
на головну. Помилковий Promise вилучається з кешу; повторна спроба зберігає
поточний URL. Повернення на головну під час помилки змінює адресу; повторне
завантаження запускається явною кнопкою.

## Стан і поточна історія

`FamilyProvider` надає перевірений набір через Context. `ViewProvider` використовує
Context/useReducer. URL визначає екран і людину; зміна `location.key` узгоджує
стан перед показом дочірніх компонентів.

- `homePersonId` незмінний протягом перегляду та береться з налаштувань.
- `personId` і `screen` описують відкриту адресу. Невідомий ID не стає центром.
- `centerPersonId` відокремлений від людини кімнати. Вхід до кімнати зберігає
  попередній центр; прямий вхід до кімнати ініціалізує його її людиною.
- `selectedRelationshipId` зберігається окремо; новий перехід скидає вибір.
- Параметри карти: початкові три покоління, zoom 1, pan (0, 0), порожній список
  згорнутих екранних появ. Зміна центру починає їх зі стандартних значень.
  Жести й керування цими параметрами реалізовано в ROD-013; pan зберігається
  у частках ширини квадратної області карти, незалежно від розміру екрана.

Посилання на іншу адресу створюють записи браузерної історії. Повторний вибір
поточної адреси не додає запису. «Назад» використовує попередній
запис поточного перегляду; browser Back/Forward відновлюють його параметри карти
й вибір зв’язку з пам’яті за `location.key`. Однакові URL можуть мати різні знімки.
Новий перехід після повернення відкидає гілку Forward. Початкове переспрямування
використовує replace, щоб не створювати зайвий крок назад.

У новій вкладці або після reload кнопка «Назад» спочатку вимкнена: застосунок
не знає попередніх знімків і не відправляє відвідувача на зовнішню сторінку.
Звичайні кнопки браузера залишаються доступними. «До мене» відкриває карту
домашньої особи, зберігаючи можливість повернутися до попередньої позиції.
Її вигляд завжди початковий: покоління з конфігурації (3), zoom 1, pan (0, 0),
без згортання й вибору зв’язку. Це діє також при переході з кімнати I1.
Якщо карта I1 вже відкрита, «До мене» скидає її на місці без нового запису.
Звичайне «Показати на карті» з кімнати того самого центру зберігає параметри.
Back/Forward відновлюють власний знімок запису, навіть якщо він був створений
дією «До мене» та згодом змінений. Ознака resetMap застосовується лише до нового переходу.

`ViewLink` залишає звичайний href і відкриття в новій вкладці; звичайний клік
проходить через спільні `goTo`/`goBack`. Повторний запит тієї самої адреси
до оновлення маршруту та повторне «Назад» під час очікування POP ігноруються.
Подвійний клік сектора не виконує другу дію в новій геометрії.

Сімейні дані та знімки перегляду не записуються в localStorage, sessionStorage,
IndexedDB чи service worker. У browser history React Router зберігає свої
службові ключі, індекс та булеву ознаку скидання вигляду; об’єкти родоводу туди не передаються.

## Узгоджений рух карти — ROD-012

`src/graph/useMapTransition.ts` виконує перехід за 420 мс одним
requestAnimationFrame для секторів, підписів та кінців ліній. Камера має
окремий SVG-transform. Поточні екранні координати перераховуються при зміні
камери; повторний перехід починається з фактично показаних координат.
Збіг шукається за appearanceId, потім за найближчою появою personId.
Нові родичі поступово з’являються на своїх місцях; центральна людина
малюється над секторами. Геометрія нових секторів задається новою проєкцією,
а їхні позиції рухаються від попереднього положення відповідної людини.
Фінальний кадр точно збігається з розкладкою ROD-010/011.

ROD-012 використовує браузерний кадровий цикл без нової залежності:
це дає спільне оновлення SVG-портів і секторів та явне скасування попереднього
переходу. Рекомендований Motion залишається можливістю для оформлення ROD-024.
При reduced motion, включно з увімкненням під час руху, фінальна геометрія
застосовується одразу. Вихід у кімнату скасовує кадровий цикл; повернення
показує збережену карту без вступної анімації. Зміна розміру екрана також
одразу застосовує нову розкладку. Зміна центру зберігає прокрутку сторінки,
водночас фокус переходить до заголовка для клавіатури й читача екрана.

## Межі реалізації й перевірки

Екрани мають теплу палітру погодженого прототипу, ім’я, видимі дії та простий
покажчик усіх 25 людей. Радіальна геометрія й переходи виконані в ROD-010–012.
Жести й керування показом реалізовано в ROD-013. Пошук, спорідненість та повний вміст кімнат виконуються наступними тікетами.
Відсутні функції позначені текстом, без вигаданих біографій чи матеріалів.

Vitest перевіряє дедуплікацію, повторні спроби, невалідні дані та відновлення
стану різних записів історії. Playwright перевіряє прямі адреси, reload, новий
вхід, Back/Forward, I1, один запит на перегляд, порожні браузерні сховища,
помилки й recovery, клавіатуру та компонування 320 px у двох профілях Chromium.
Знімки карти й кімнати зберігаються в `test-results/` під час сценарію навігації.

`center-history.spec.ts` перевіряє I1 → I2 → I3 → Назад → Back/Forward →
До мене, прямий вхід у кімнату, повторні кліки й поточну адресу, скидання
вибору зв’язку, переривання переходу та reduced motion у двох профілях Chromium.
Керований час дозволяє звірити рух вузла й лінії та точний фінальний стан;
зберігаються початковий, проміжний та кінцевий кадри. Відновлення поколінь,
zoom/pan і згортання покрите reducer-тестами та браузерними сценаріями ROD-013.

## Керування картою — ROD-013

`src/graph/useMapCamera.ts` підключає d3-zoom до SVG. React володіє transform
камери; d3 передає жести в reducer та отримує оновлену початкову позицію після
кнопок, історії, зміни центру й розміру. Проєкція залежить лише від центру,
поколінь і згортання та не перераховується при кожному русі камери.
Положення зберігається у частках ширини карти, тому resize зберігає відносну
позицію та масштаб. Вхід до кімнати й повернення не змінюють камеру.

- Кнопки −/+ змінюють масштаб навколо центру в межах 50–600%; стрілки
  пересувають карту на 12% її ширини. Усі кнопки доступні клавіатурою й дотиком.
- «Вмістити карту» повертає zoom 1 / pan (0, 0), зберігаючи покоління та згортання.
  «До мене» застосовує повне скидання ROD-012.
- Перетягування лівою кнопкою або одним пальцем пересуває карту; два пальці
  та Ctrl + колесо змінюють масштаб. Звичайне колесо прокручує сторінку,
  а на сенсорному екрані сторінка прокручується поза областю карти.
- d3 відсікає клік після руху миші понад 6 px; обробник capture також
  відсікає сумісні кліки після руху пальця / pinch. Подвійне натискання
  не додає другого переходу. Жест чи кнопка камери під час зміни центру
  завершує рух секторів і ліній разом, без конфлікту SVG-transform.
- Поле «Покоління» задає глибину 1–12 у чинній секторній проєкції. Початкова
  глибина — 3; подружжя має те саме генеалогічне покоління. Навіть при одному
  видимому центрі покажчик містить усі 25 людей; пошук буде додано в ROD-014.
- Розділ «Гілки карти» містить нумеровані появи з повними іменами, напрямом,
  батьківським сектором, кнопкою згортання / розгортання та поясненням прихованого
  продовження. Згорнутий сектор залишається на карті. Стан прив’язаний до
  appearanceId, тому повторні появи тієї самої людини незалежні. При тимчасовому
  зменшенні глибини згортання зберігається; «Розгорнути всі гілки» очищає його
  також для тимчасово невидимих появ. Для прихованих через глибину родичів є
  підказка збільшити покоління; для бічних — змінити центр.

`map-controls.spec.ts` перевіряє ці сценарії, відновлення історії й кімнати,
межі масштабу, resize 1024 → 320, рух камери під час анімації та наступний
жест після скидання. Touch-сценарій подає нативні події Chromium через CDP
у профілі Pixel 7: drag, pinch, відсутність випадкової навігації й прокручування
поза картою. Він пропущений лише у профілі без touch. Це емуляція;
перевірка на фізичному телефоні залишається умовою приймання ROD-013.
