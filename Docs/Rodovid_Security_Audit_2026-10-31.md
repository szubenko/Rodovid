# Аудит безпеки: приватний тест через Vercel Authentication

Дата: **31.10.2026**. Обсяг: код, конвеєр статичної збірки, конфігурація деплою,
видача даних і браузерне зберігання. Налаштування Vercel виконує власник;
доступу до його dashboard і фактичного deployment URL у цій роботі немає.
Це аудит репозиторію та підготовка перевірок, а не підтверджений pentest хостингу.

Модель: єдиний відвідувач — власник. Сторонній користувач, навіть із власним
Vercel account, не має отримувати HTML застосунку, JSON, фото, PDF чи аудіо.
Завантаження/редагування даних через UI, власного API і серверної БД немає.

## Переглянуті механізми

- `static-data-plugin.ts` запускає свіжу конвертацію/валідацію й видає тільки
  JSON та оголошені матеріали; `assets.ts` перевіряє realpath під assets,
  розширення й сигнатуру. Сирі GEDCOM/RootsMagic не копіюються до вебресурсів.
- Схема дозволяє локальні шляхи матеріалів і лише HTTP(S) зовнішні URL.
  Markdown обробляє `react-markdown` із `skipHtml`, обмеженим набором тегів
  та `noopener noreferrer`. Довільного raw HTML із сімейного тексту немає.
- Текст місць Leaflet задається через `textContent`; читання `innerHTML`
  атрибуції використовується після створення DOM із фіксованими посиланнями,
  а не для вставлення неперевіреного HTML родоводу.
- Карта використовує локальні GeoJSON. Автоматичних запитів до FamilySearch,
  сторонніх тайлів, remote fonts, аналітики чи telemetry SDK у переглянутому
  коді немає; переходи за зовнішніми посиланнями виконує користувач.
- `load-family.ts` використовує same-origin fetch із `cache: no-store`;
  JSON зберігається в пам'яті сторінки. localStorage містить лише налаштування
  звуку, service worker/Cache API/постійного офлайн-кешу сімейних даних немає.
  Пам'ять уже відкритої сторінки сама не очищується при закінченні cookie.
- Приватні ключі/токени не знайдені вибірковим пошуком поширених сигнатур
  у текстових файлах src/scripts/Data/Docs; tracked `.env`/ключів немає.
  Це не повний аналіз Git history або підтвердження відсутності всіх секретів.
- Залежності зафіксовані lockfile; віддалена збірка використовує npm ci,
  Node major 24 та зафіксований npm. Автоматичний `npm audit fix` не виконувався.

## Перевірки та межі

Підсумкові виконані команди й результати записані в
[ROD-030](tickets/030-vercel-config.md). Тести охоплюють відсутність сімейних
даних у smoke, видалення застарілих файлів, відмову на невідомі режими/файли,
свіжий статичний конвеєр і сумісність CSP з основними переглядачами.

Локальний preview застосовує такі самі response headers, але не відтворює
Vercel edge authentication, provider cookies, CDN чи platform rewrites.
Доступ без входу/без дозволу, заголовки на платформі, всі aliases,
завершення сесії та приватність Git потребують перевірки власником.
Захисні заголовки не замінюють автентифікацію; noindex не обмежує доступ.

## Умови переходу до family на Vercel

Виконати матрицю ROD-031 на нешкідливій заглушці, перевірити membership/bypass,
приватність Git та погодити результат ROD-032 щодо виходу/сесії.
Не оголошувати ROD-031…034 виконаними лише за локальними тестами.
Детальні кроки, URL і протокол — у
[інструкції деплою](Rodovid_Vercel_Deployment.md).
