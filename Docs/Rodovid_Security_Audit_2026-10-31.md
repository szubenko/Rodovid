# Аудит безпеки: приватний тест через Vercel Authentication

Дата: **31.10.2026**. Обсяг: код, конвеєр статичної збірки, конфігурація деплою,
видача даних і браузерне зберігання. Налаштування Vercel виконує власник;
доступу до його dashboard і фактичного deployment URL у цій роботі немає.
Це аудит репозиторію та підготовка перевірок, а не підтверджений pentest хостингу.

**Наступне рішення власника 31.10.2026:** заглушку скасовано, перша збірка
одразу містить повний сімейний атлас. Режимів/RODOVID_DEPLOY_MODE немає.
Попередні протоколи smoke нижче збережені як історія аудиту;
чинний порядок — у [інструкції деплою](Rodovid_Vercel_Deployment.md).
Для поточного варіанта пройшли 3 профільні тести, lint, повна збірка
та 4 браузерні сценарії; у результаті 260 файлів, 102 людини й 88 медіазаписів,
валідація без помилок. Регресія чистої збірки створює JSON із вихідних даних
до перевірки типів і відхиляє вставлену помилку типів.

Модель: єдиний відвідувач — власник. Сторонній користувач, навіть із власним
Vercel account, не має отримувати HTML застосунку, JSON, фото, PDF чи аудіо.
Завантаження/редагування даних через UI, власного API і серверної БД немає.

## Переглянуті механізми

- `static-data-plugin.ts` запускає свіжу конвертацію/валідацію й видає тільки
  JSON та оголошені матеріали; `assets.ts` перевіряє realpath під assets,
  розширення й сигнатуру. Сирі GEDCOM/RootsMagic не копіюються до вебресурсів.
- Схема дозволяє локальні шляхи матеріалів і лише HTTP(S) зовнішні URL.
  Markdown обробляє `react-markdown` із `skipHtml`, обмеженим набором тегів
  та `noopener noreferrer`. Довільного raw HTML із сімейного тексту немає.
- Текст місць Leaflet задається через `textContent`; читання `innerHTML`
  атрибуції використовується після створення DOM із фіксованими посиланнями,
  а не для вставлення неперевіреного HTML родоводу.
- Карта використовує локальні GeoJSON. Автоматичних запитів до FamilySearch,
  сторонніх тайлів, remote fonts, аналітики чи telemetry SDK у переглянутому
  коді немає; переходи за зовнішніми посиланнями виконує користувач.
- `load-family.ts` використовує same-origin fetch із `cache: no-store`;
  JSON зберігається в пам'яті сторінки. localStorage містить лише налаштування
  звуку, service worker/Cache API/постійного офлайн-кешу сімейних даних немає.
  Пам'ять уже відкритої сторінки сама не очищується при закінченні cookie.
- Приватні ключі/токени не знайдені вибірковим пошуком поширених сигнатур
  у текстових файлах src/scripts/Data/Docs; tracked `.env`/ключів немає.
  Це не повний аналіз Git history або підтвердження відсутності всіх секретів.
- Залежності зафіксовані lockfile; віддалена збірка використовує npm ci,
  Node major 24 та зафіксований npm. Автоматичний `npm audit fix` не виконувався.

## Аудит залежностей і виправлення — 31.10.2026

Після явного дозволу власника виконано `npm audit --json` через офіційний
`registry.npmjs.org`, окремо — `npm audit --omit=dev --json`.
Попередню перешкоду дозволів знято; назви/версії залежностей передано
реєстру в межах погодженого аудиту, сімейні файли не передавалися.

| Набір | Critical | High | Moderate | Разом |
| --- | ---: | ---: | ---: | ---: |
| Повне дерево до виправлень | 0 | 5 | 14 | 19 |
| Повне дерево після виправлень | 0 | 0 | 12 | 12 |
| Production після виправлень (`--omit=dev`) | 0 | 0 | 0 | 0 |

Це кількість позначених пакетів npm, включно з транзитивними ефектами;
вона не дорівнює кількості незалежних вразливостей чи доступних з інтернету атак.

Внесено сумісні оновлення й зафіксовано новий lockfile:

| --- | --- | --- | --- |
| zod | 4.5.4 | 4.6.7 | Валідація підготовлених даних; production |

| source-map-js | 1.2.1 | 1.2.2 | Транзитивна залежність PostCSS у збірці |

Zod усуває [GHSA-mrhx-c7xc-m3w5](https://github.com/advisories/GHSA-mrhx-c7xc-m3w5),
image-size — [GHSA-5p2g-fcmc-qvqq](https://github.com/advisories/GHSA-5p2g-fcmc-qvqq)
та [GHSA-w3rx-r6r6-pgpr](https://github.com/advisories/GHSA-w3rx-r6r6-pgpr).
Оновлення Vite усуває позначки його dev server / launch-editor, зокрема
[GHSA-587h-7wmj-h5pm](https://github.com/advisories/GHSA-587h-7wmj-h5pm).
Vercel видає статичний результат, а не запущений Vite dev server.

Залишився один кореневий advisory:
[minimatch GHSA-g3hv-75wg-m249](https://github.com/isaacs/minimatch/security/advisories/GHSA-g3hv-75wg-m249).
За описом автора атака потребує контрольованого зловмисником glob-патерна
та `optimizationLevel >= 2`. У переглянутих викликах @eslint/config-array
і @typescript-eslint/typescript-estree задається `dot: true`, без цього
підвищеного рівня; встановлений minimatch за замовчуванням використовує 1.
Це знижує застосовність до поточного запуску lint, але не прибирає advisory
зі звіту пакета. Сайт не приймає glob-патерни від відвідувача; цей ланцюжок
належить інструментам розробки і не входить до браузерної збірки.

Офіційно виправлений minimatch — 11.0.1, тоді як ESLint/TypeScript-ESLint
декларують 10.x. Перевірені актуальні eslint 10.14.0 і typescript-eslint 8.72.1
не дали сумісного рішення цього діапазону. Автоматичний force/downgrade
чи override на непідтримуваний major не застосовувалися.
До наступного оновлення upstream запускати lint лише над довіреним checkout
і конфігурацією; залишок не оголошувати нульовим аудитом усього проєкту.

Повні локальні результати: `tmp/security-npm-audit-2026-10-31-before.json`,
`tmp/security-npm-audit-2026-10-31.json`,
`tmp/security-npm-audit-production-2026-10-31.json`.
`npm audit` після виправлень повертає 1 через moderate; production-аудит — 0.
Встановлення виконано без lifecycle-скриптів; `npm audit fix --force` не запускався.

## Перевірки та межі

Після оновлень пройшли типи, lint, family build (260 файлів) і smoke build
(5 файлів), 4 браузерні сценарії Chromium desktop/Pixel 7 з CSP та
170 цільових модульних перевірок у восьми suites: schema, load-family,
build-vercel, static-data-plugin, reimport, import-export-6, petro-birth-1900,
relatives. JSON родоводу після family build побайтово незмінний.

Широкі запуски з типовим паралелізмом і двома workers зупинено після таймаутів;
вони не зараховані як успішна повна регресія. Цільовий повтор виконано
з `--maxWorkers=1 --testTimeout=30000 --reporter=verbose`;
усі 170 перевірок пройшли, зокрема попередні збої імпорту/геометрії.
Тести й їхні твердження не послаблювалися, конфігурація таймаутів репозиторію
не змінювалася. Журнал — `tmp/security-focused-tests-2026-10-31.log`.
Після перевірок `dist-vercel` повернуто до п'яти нешкідливих probe-файлів.

За логом реального Vercel build додатково виправлено залежність перевірки
типів від локального generated JSON. `build:vercel` та інші build-команди
тепер використовують строгий `typecheck:build` без test/spec-файлів.
П'ять профільних тестів пройшли; новий регресійний сценарій виконує npm build
на ізольованій копії без Data/generated/tests і попереднього кешу, перевіряє
п'ять probe-файлів та відмову TS2322 при вставленій помилці типів у коді сайту.
Lint, smoke build і повний локальний typecheck після підготовки даних успішні.
Отже, smoke не потребує підготовки чи читання сімейного архіву навіть у
чистому checkout. Фактичний повторний Vercel build ще має підтвердити власник.

Підсумкові виконані команди й результати записані в
[ROD-030](tickets/030-vercel-config.md). Тести охоплюють відсутність сімейних
даних у smoke, видалення застарілих файлів, відмову на невідомі режими/файли,
свіжий статичний конвеєр і сумісність CSP з основними переглядачами.

Локальний preview застосовує такі самі response headers, але не відтворює
Vercel edge authentication, provider cookies, CDN чи platform rewrites.
Доступ без входу/без дозволу, заголовки на платформі, всі aliases,
завершення сесії та приватність Git потребують перевірки власником.
Захисні заголовки не замінюють автентифікацію; noindex не обмежує доступ.

## Чинний порядок публікації

За явним рішенням власника розгортається одразу повний сімейний атлас,
а матриця ROD-031 та вихід/сесія ROD-032 перевіряються на ньому.
Vercel Authentication / All Deployments та приватність вихідного Git
залишаються частиною обраного підходу. Dashboard налаштовує власник.
Не оголошувати ROD-031…034 виконаними лише за локальними тестами.
Детальні кроки, URL і протокол — у
[інструкції деплою](Rodovid_Vercel_Deployment.md).
