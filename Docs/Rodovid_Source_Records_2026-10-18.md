# Єдине зберігання джерел — 18.10.2026

Власник погодив один JSON на запис із двома полями `url` і `description`,
необов’язковий скан, імпорт описів із GEDCOM та збереження ручних правок
під час повторних імпортів. Редагування й підготовка залишаються локальними.

## Реалізовано

- У `Data/assets/documents/source-records/` є 62 JSON-файли, створено 60
  нових. 13 описів непорожні; решта джерел наразі мають посилання без опису.
- Для Анастасії створено
  `карпінська-анастасія-народження-PN7G-3MV-33S7-9R9B-QZW.json` із наявним
  посиланням і текстом. Скан відсутній; його не завантажували й не вигадували.
- Наявні описи та посилання перенесені з `annotations.json` у файли;
  доповнення містять зв’язки з джерелами, подіями, людьми та твердженнями.
  Одне джерело може використовувати один файл у кількох контекстах.
- Дані сайту читають поточні поля з файлів. Сирі нотатки та бібліографія
  залишаються у GEDCOM. Повторний текст у кількох цитуваннях однієї події
  відображається один раз.
- `source:sync` і підготовка даних застосовують порівняння трьох варіантів
  окремо для URL та опису: попередній імпорт, поточний файл, новий імпорт.
  Ручний текст зберігається; нерозв’язаний конфлікт повторюється у звіті.
  `--keep-local` або `--use-import` явно фіксують рішення.
- Порожні поля й пропущене джерело не видаляють текст, файли та збережені
  прив’язки. Службовий `Data/source-record-imports.json` містить базу порівняння
  та останні імпортовані джерела з посиланнями для відновлення пропусків.
- Доданий поруч із JSON скан реєструється під час наступної підготовки.
  Окремі джерела не зливаються за спільним кадром чи URL. Підтримуються
  індекси, кадри FamilySearch та локальні документи без URL (`null`).

## Збереження та відновлення

Основна резервна копія до перенесення:
`tmp/source-record-sync/1792327379659-5676/`.
У ній є старі доповнення та `changes.json` з переліком створених файлів.
Підпапка `naming-corrections/` зберігає стан перед уточненням двох нових назв:
документ шлюбу названий за Степаном — учасником подружнього зв’язку,
а знімок родини без події шлюбу має тип `інша-подія`.
Наступні застосування також створюють резервну копію змінених файлів.

Оригінальний GEDCOM, ідентичності, налаштування родоводу, факти, оцінки,
місця та медіа збережені. Перевірка старих доповнень підтвердила збереження
всіх 19 початкових текстових фрагментів у нових описах та всіх наявних URL.
Описи знімка родини з кількома цитованими уривками зібрані в один JSON
без втрати тексту. Історична достовірність автоматично не підвищувалась.

## Перевірки

- 36 профільних тестів: синхронізація, ручні зміни, конфлікти й обидва
  способи їх розв’язання, пропущене та повернуте джерело, редагування
  збереженого джерела, спільний кадр різних актів, додавання скану пізніше,
  локальний майстер, CLI, попередні імпорти та статична підготовка.
- 49 тестів схеми й чистого конвертера GEDCOM.
- Lint, TypeScript, стандартна production-збірка та збірка сімейного атласу.
- Чотири браузерні сценарії desktop/mobile: опис і посилання Анастасії без
  картинки, розшифровка й справний скан Наталії, відсутність редактора,
  відсутність горизонтального прокручування. Знімки Анастасії оглянуті.
- На поточних даних немає конфліктів або помилок валідації; повторна
  синхронізація не створює і не змінює файлів. Службові JSON не потрапляють
  до статичної збірки.
