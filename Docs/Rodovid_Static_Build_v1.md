# Статична збірка й матеріали Rodovid v1

**Дата:** 2026-09-09. **Тікет:** [ROD-007](tickets/007-static-build-assets.md).

## Команди та результат

```sh
npm run build
npm run preview
```

`build` перевіряє TypeScript і запускає Vite. Плагін
[`staticDataPlugin`](../scripts/static-data-plugin.ts) перед створенням результату
заново запускає конвертер із поточними `Data/Zubenko.ged`, `site.json`,
`annotations.json`, `identities.json` і матеріалами `Data/assets/`.
Конвертер виконує всі перевірки ROD-006; за помилки Vite завершується з кодом 1.
Навіть прямий `npx vite build` проходить підготовку даних. Старий
`generated/family.json` не використовується як вхід.

Конвертер має параметр `--project-root` для вибору кореня проєкту без
перетворення відносного імені `Data/annotations.json` у машинний шлях
у записах походження. Звичайні команди використовують поточний репозиторій.

Звіт залишається в `tmp/data-conversion.json` та `.json.md`, робочий JSON —
у `generated/family.json`. Обидва каталоги виключені з Git. Результат:

```text
dist/
  index.html
  app-assets/        JS/CSS застосунку з хешами в назвах
  data/family.json   поточний перевірений набір
  assets/            лише оголошені повні матеріали й мініатюри, якщо є
```

Копіювання `public/` вимкнено. GEDCOM, RootsMagic, архівні оригінали,
журнал ID, звіти й тестові приклади не переносяться. Успішна збірка очищає
попередній `dist/`: вилучені декларації та перейменовані файли не залишаються.
За невдалої перевірки даних попередній успішний `dist/` може залишитися;
це старий результат, його не слід приймати за нову збірку.

`preview` показує готовий результат на <http://127.0.0.1:4173> без конвертації.
Після оновлення входу повторіть `build` і перезавантажте сторінку.
`dev` також готує дані при запуску й обслуговує ті самі URL з пам’яті.
Після додавання, зміни або вилучення файлів у `Data/` плагін повторно
запускає конвертацію й валідацію, цілком замінює підготовлений набір у пам’яті
та надсилає повне перезавантаження сторінки. Так нові назви й матеріали
одночасно потрапляють до кімнати, попапа та інших споживачів JSON.
Короткі серії файлових змін об’єднуються; конвертації виконуються послідовно.
За помилки валідації останній успішний набір залишається доступним,
а браузер і термінал показують помилку. Після виправлення оновлення
відновлюється без перезапуску сервера. Гаряче оновлення `src/` працює як раніше.

## Постійне сховище та URL

`Media.path = assets/documents/record.pdf` означає файл
`Data/assets/documents/record.pdf` і URL `assets/documents/record.pdf` від
кореня розміщення застосунку. JSON доступний як `data/family.json`.
При майбутній маршрутизації URL слід будувати від `import.meta.env.BASE_URL`,
а не від вкладеної адреси кімнати. Шляхи Windows, `Downloads`, `..`,
зворотні слеші та довільні зовнішні URL у полях файлів заборонені схемою.

Матеріал оголошують один раз у `annotations.json.media`, його `id`
використовують у фото людей, подіях, джерелах, спогадах чи налаштуваннях.
Кілька прив’язок і навіть кілька медіазаписів з однаковим шляхом дають один
фізичний файл у збірці. Колізії регістру назв блокуються для сумісності
Windows і Linux. JS/CSS мають окремий каталог `app-assets/`.

Перевіряються основні файли та мініатюри: шлях усередині `Data/assets/`
після розкриття символічних посилань, звичайний непорожній файл, відповідне
розширення і сигнатура JPEG/PNG/PDF/MP3/Ogg/WAV. Файл перечитується й
перевіряється перед додаванням до збірки; копіюються саме перевірені байти.
Сигнатура не замінює повного декодування та візуального перегляду матеріалу.

## Мініатюра, повний матеріал, архівний оригінал

| Призначення | Постійна папка | Контракт і підготовка |
| --- | --- | --- |
| Повне фото | `Data/assets/photos/` | `Media.path`, JPEG або PNG; підготовлена копія для збільшення. |
| Читабельний скан/PDF | `Data/assets/documents/` | `Media.path`; зберегти роздільність, за якої читається дрібний текст. Збірка не стискає, не обрізає й не перекодовує файл. |
| Мініатюра фото чи PDF | `Data/assets/thumbs/` | Необов’язковий `Media.thumbnail = { path, mimeType }`, JPEG або PNG. Готувати окремо, орієнтир — до 480 px по довшій стороні; для PDF — обрана сторінка. |
| Архівний оригінал | `Data/originals/` або сімейний архів поза проєктом | Не оголошувати як матеріал сайту; зберігати окремо й резервувати разом із джерелами. |

Мініатюри готуються поза збіркою та зберігаються як постійні матеріали;
автоматичного перекодування немає. Це залишає скани незмінними й робить
копіювання відтворюваним без бібліотек обробки зображень. Якщо мініатюри
немає, майбутня галерея використовує повне фото або заглушку документа.
Оголошена, але відсутня мініатюра є помилкою. Для аудіо мініатюра не допускається.

Якщо матеріалів узагалі немає, порожні колекції в JSON є коректним станом,
папка `Data/assets/` не потрібна. Реальний початковий набір саме такий.
Сімейні матеріали та їхня читабельність перевірятимуться в ROD-026;
синтетичні файли перевірок не є сімейними джерелами.

## Перевірки

Інтеграційні тести збирають ізольований тимчасовий проєкт через фактичну
конфігурацію Vite: спільні файли, мініатюри, PDF, побайтова заміна, повторна
збірка, нова версія налаштувань, порожній набір, відсутній файл, хибна
сигнатура, замасковане розширення та колізія регістру. Перевіряються склад
результату, відсутність зайвих файлів і HTTP-відповідь dev-сервера.
Зміна української назви в доповненнях під час роботи сервера перевіряє
новий HTTP-вміст і повідомлення перезавантаження; некоректне доповнення —
повідомлення помилки, збереження останнього набору й відновлення після виправлення.
Playwright перевіряє готовий застосунок, JSON і всі оголошені матеріали
через preview на комп’ютерному й мобільному профілях.

Технічні джерела: [Vite Plugin API](https://vite.dev/guide/api-plugin.html),
[Vite build options](https://vite.dev/config/build-options.html).
Публікація й захист доступу залишаються обсягом ROD-029…ROD-034.
