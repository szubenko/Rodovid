## Мета

Узгодити єдину модель даних для перетворювача, карти, кімнат і доказів.

## Обсяг роботи

- Описати TypeScript/Zod-схеми людини, зв’язку, твердження, події, місця, джерела/документа, прив’язки доказу, спогаду та налаштувань.
- Задати домашню особу через @I1@; явно описати відображення GEDCOM ID в адресах на кшталт I1 і збереження походження записів.
- Визначити формат дат, основних і альтернативних тверджень, чотирьох рівнів достовірності та необов’язкових полів.
- Описати site/config, доповнення й явне зіставлення ID після повторного експорту; персональні дані залишаються у GEDCOM, generated JSON не редагується вручну.

## Критерії приймання

- [ ] Усі сутності з §12.3 ТЗ мають схему та зрозумілі зв’язки між ID.
- [ ] Один документ підтримує кілька прив’язок, одна людина — кілька екранних появ із спільним personId.
- [ ] Збережені початковий текст дати, точність/невизначеність і невідомий життєвий статус.
- [ ] Відсутня оцінка означає «Не оцінено»; QUAY не отримує автоматичного взаємно однозначного перетворення без окремого правила.
- [ ] Приклади даних містять альтернативу, спільний документ і зміну ID; синтетичні приклади відокремлені від сімейного набору.

## Перевірка

Перевірити схеми на мінімальному, повному й некоректному прикладах; звірити модель з усіма сутностями ТЗ.
