## Мета

Зафіксувати рішення або явну невизначеність для всіх відомих проблем, щоб інтерфейс не видавав припущення за факти.

## Обсяг роботи

- Розібрати D01: F6/F7, D02: F8/F9 і D03: I6 як дружину та дитину I9; показати власнику конкретні записи та наслідки.
- Окремо розглянути D04 «Сегрій», D05 дати I22 та зв’язок з I20, D06 написання й координати місць.
- Створити реєстр: вихідні ID, спостереження, рішення власника/статус «не з’ясовано», підстава та правило показу.
- Підтверджені виправлення виконувати лише поза сайтом зі збереженням попередньої версії; підготувати зіставлення ID за потреби.

## Критерії приймання

- [x] Кожне D01–D06 має запис у реєстрі та явний результат розгляду.
- [x] Без підтвердження власника імена, дати й родинні ролі не виправлені автоматично.
- [x] Для невирішених D01–D03 визначено позначення проблеми та заборону безумовних точних підписів спорідненості через ці зв’язки.
- [x] Дублікати й суперечності залишаються простежуваними до вихідних записів; спосіб їх показу описаний.
- [x] За відсутності історичного висновку зафіксовано невизначеність і відповідального за уточнення; це дозволяє продовжити прототип із відповідними обмеженнями.

## Перевірка

Звірити реєстр з усіма шістьма зауваженнями; для змінених даних переглянути різницю з попередньою версією.

## Результат і блокери

Створено [реєстр D01–D06](../Rodovid_Data_Decisions_2026-09-09.md) з конкретними
вихідними записами, підставами, наслідками та правилами показу. Власнику наведено
склад F6/F7 і F8/F9, ролі I6/I9, написання I1, дати I20/I22 та всі вісім місць.
Кожне питання має явний результат «Не з’ясовано» та відповідального — власника
родоводу. Підтверджених виправлень немає; автоматичних змін або злиття не виконано.

Перевірки: `npm run data:check-gedcom` пройшла (1156 рядків, 25 людей, 9 сімей,
32 прив’язки дітей, 48 подій); сім’ї/діти, дати D05 та місця звірено з робочою
базою лише для читання. SHA-256 обох файлів збігаються з початковим оглядом.
Локальні Markdown-посилання, критерії, прогрес і `git diff --check` перевірено.
Код не змінювався; перевірки збірки та UI не потрібні.

Блокерів для ROD-005 немає. Історичні уточнення залишаються відкритими;
позначення проблем і заборона безумовних точних підписів мають бути реалізовані
наступними тікетами за реєстром. Виконання ROD-004 не означає підтвердження даних.
