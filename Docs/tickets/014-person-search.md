## Мета

Знаходити будь-яку людину з повного родоводу незалежно від поточної видимості карти.

## Обсяг роботи

- Створити локальний індекс імен, прізвищ, по батькові та підготовлених альтернативних написань.
- Нормалізувати регістр і пробіли для пошуку, зберігаючи оригінальне написання в результатах.
- Додати список результатів, відсутність збігів, очищення запиту та клавіатурний вибір.
- При виборі результату зробити людину видимим центром із записом переходу в історію.

## Критерії приймання

- [x] Знаходяться всі 25 людей, включно з прихованими та старшими гілками.
- [x] Пошук за основним або підготовленим альтернативним іменем веде до того самого personId.
- [x] Однакові імена можна розрізнити за наявними роками/відомостями без вигаданих уточнень.
- [x] Порожній запит і відсутність результатів мають зрозумілі стани; пошук не виправляє історичні імена.
- [x] Після переходу з пошуку працюють «Назад» і «До мене» на комп’ютері та телефоні.

## Перевірка

Перевірити частину імені, інший регістр, альтернативне написання, приховану людину, однакові імена й відсутність збігів.

## Результат і блокери

2026-09-13, Codex: виконано всі п’ять критеріїв. Пошук доступний над картою
й кімнатою та охоплює повний набір незалежно від видимих поколінь і гілок.

- [Локальний індекс](../../src/search/people.ts) шукає частини імен, прізвищ,
  по батькові та всіх підготовлених альтернативних написань. Нормалізація
  регістру, пробілів і Unicode NFC не змінює вихідні імена; кожен personId
  з’являється один раз. Слова не змішуються між різними альтернативами.
- [Інтерфейс](../../src/search/PersonSearch.tsx) показує основне ім’я,
  наявні роки життя та інші написання. Тезки залишаються окремими результатами;
  невідомі й альтернативні дати позначено без вигаданих відомостей.
- Порожній запит, відсутність збігів, очищення, Tab/Enter/пробіл,
  стрілки вгору/вниз, Escape й оголошення кількості результатів доступні
  з клавіатури. Вибір показує центр у початковому вигляді; попередні камера,
  покоління та гілки відновлюються через історію. Пошук не зберігається
  між переходами, у URL чи браузерних сховищах.
- Спільне читання основного імені винесено в
  [person-name.ts](../../src/data/person-name.ts), щоб чисті функції пошуку
  й Node-перевірки не залежали від браузерного завантажувача.
  Поведінку описано в [документації навігації](../Rodovid_Navigation_v1.md#пошук-людей--rod-014).

Перевірено:

- `npm test`: 199/199, включно з реальними 25 людьми та синтетичними
  альтернативними іменами, по батькові, тезками й невідомими датами.
- `npm run test:e2e`: 61 успішний, 1 очікуваний пропуск touch-сценарію
  ROD-013 у desktop-профілі. Усі 8 браузерних прогонів ROD-014 успішні
  у desktop і mobile Chromium: пошук усіх 25 людей, відновлення історії,
  кімната, альтернативи, клавіатура й компонування 320 px.
- `npm run lint`, типи та production build (у повному e2e-прогоні) — успішні.
  Початковий тест читав список до завантаження даних; додано очікування
  готовності, після чого весь набір пройшов повторно.
- Візуально оглянуто `search-320.png` і `search-namesakes.png` у `test-results/`:
  текст і кнопки вміщуються, роки та фокус читабельні. Синтетичні імена
  існують лише у fixtures/перехопленій відповіді тесту й не потрапляють до збірки.
- `npm run data:check-gedcom`: незмінні SHA-256 та 1156 рядків,
  25 людей, 9 сімей, 48 подій. GEDCOM/RootsMagic не змінено.

Блокерів реалізації немає. На запит власника про наступний тікет використано
готову реалізацію ROD-013. Її окреме приймання на фізичному телефоні залишається
відкритим; мобільні перевірки цього тікета виконані в емуляції Pixel 7 та на
ширині 320 px і не є заявою про перевірку фізичного пристрою. Наступний тікет — ROD-015.
