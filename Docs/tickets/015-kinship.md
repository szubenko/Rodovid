## Мета

Пояснювати зв’язок обраної людини з власником із чесним показом невизначеності.

## Обсяг роботи

- Розраховувати шлях від постійного homePersonId, незалежно від поточного центру.
- Підтримати погоджені базові родинні ролі; для складнішого шляху показати зрозумілий ланцюжок людей і зв’язків.
- Враховувати непевні твердження та результати D01–D03; не обирати мовчки один із суперечливих шляхів.
- Додати стан відсутнього шляху та обмежити обхід циклів.

## Критерії приймання

- [x] Зміна центру не змінює точку відліку пояснення — власника I1.
- [x] На перевірених прикладах правильно показані батьки, предки, діти й бічні зв’язки.
- [x] Шлях через невирішений D01–D03 не отримує безумовного точного підпису; причина невизначеності видима.
- [x] Кілька суперечливих шляхів або відсутність шляху пояснені без вигаданого споріднення.
- [x] Повторні предки й цикли не спричиняють нескінченного пошуку.

## Перевірка

Vitest для основних ролей, неоднозначного шляху, ізольованої людини й циклу; реальні проблемні зв’язки перевірити за реєстром.

## Результат і блокери

Виконано 2026-09-13. [Пояснення спорідненості](../Rodovid_Navigation_v1.md#спорідненість--rod-015)
доступне на карті та в кімнаті; точка відліку завжди `config.homePersonId`.

- `src/kinship/kinship.ts`: базові родинні ролі, усі прості кровні шляхи
  через спільних предків, пряме подружжя та короткі ланцюжки складних зв’язків.
  Стать не вгадується за іменем; назви ролей парні.
- `src/kinship/KinshipExplanation.tsx` і CSS: альтернативи, видимі пояснення
  D01–D03/D05, оцінки кожного запису, вихідні FAM та переходи до кімнат.
  Паралельні записи згруповано тільки для кроку обходу, всі ребра збережено.
- Точний безумовний підпис відсутній для неприйнятих/непідтверджених ребер,
  різних ролей або поколінь і за неповного пошуку. Повторний предок не
  втрачається; цикл завершується. Порожній шлях відрізняється від ліміту.
- Обхід кровних шляхів не обмежений початковими трьома поколіннями.
  Для складних шлюбних зв’язків поза цим словником показуються найкоротші
  ланцюжки без висновку про батьківство. Ліміт 10000 станів явно позначає
  неповний результат; на всіх 25 реальних людях його не досягнуто.

Перевірено:

- `npm test`: 233/233, зокрема 29 синтетичних тестів спорідненості та
  5 перевірок реального набору: всі 25 людей, два шляхи до Макара
  (3 і 4 покоління, D03/F5), D01/F6/F7, D02/F8/F9 і D05 для I22.
- `npm run test:e2e`: 69 успішних, 1 очікуваний пропуск desktop touch-сценарію.
  Усі 8 нових прогонів у desktop/mobile Chromium успішні: постійна I1,
  пошук, кімната, історія, клавіатура, дублікати, оцінки й відсутній шлях.
- `npm run lint`, `npm run typecheck`, production build у повному e2e-прогоні
  та `git diff --check` успішні. Початковий конфлікт резолюції назв файлів
  Kinship/kinship на Windows усунуто окремою назвою KinshipExplanation.
- Оглянуто знімки `kinship-map-1024.png`, `kinship-320.png` і розгорнуті
  деталі в `test-results/`; текст переноситься, горизонтального переповнення
  на 320 px немає. Мобільні перевірки виконані в емуляції.
- `npm run data:check-gedcom`: незмінні SHA-256, 1156 рядків, 25 людей,
  9 сімей і 48 подій. GEDCOM/RootsMagic та сімейні доповнення не змінено.

Блокерів ROD-015 немає. Невирішені історичні питання залишаються за реєстром
і явно показані в інтерфейсі. Приймання ROD-013 на фізичному телефоні
залишається відкритим. Наступний тікет — ROD-016.
