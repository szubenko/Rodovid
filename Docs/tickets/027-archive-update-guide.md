## Мета

Дати власнику відтворюваний порядок ручного оновлення архіву та повернення до попередньої версії.

## Обсяг роботи

- Описати, де лежать GEDCOM, налаштування, доповнення, матеріали, згенеровані дані та звіт.
- Оформити послідовність: резервна копія → ручне оновлення → зіставлення ID за потреби → перевірка → build → локальний перегляд.
- Додати інструкцію читання помилок/попереджень, заміни матеріалів і виправлення неприв’язаних доповнень.
- Описати резервування вихідних даних і всіх матеріалів, відновлення та окреме зберігання архівних оригіналів.

## Критерії приймання

- [ ] За інструкцією можна отримати локальну оновлену версію без редагування generated JSON.
- [ ] Повторний експорт не втрачає людей, зв’язки, альтернативи, докази й матеріали; перепризначені ID мають явне зіставлення.
- [ ] При помилці даних власник розуміє, який вихідний запис або файл виправити.
- [ ] Відновлення перевірене на окремій копії та охоплює дані разом із матеріалами.
- [ ] Інструкція не додає імпорт, експорт, редактор або кнопки резервування до сайту.

## Перевірка

Пройти інструкцію на копії: змінити підготовлений матеріал, повторно зібрати, перевірити результат і відновити попередній стан.

## Результат і блокери

Роботу ще не розпочато. Під час виконання записати результат, посилання на зміни або артефакти, виконані перевірки та залишкові обмеження. Якщо виник блокер — указати причину, потрібне рішення й відповідального. Статус і прогрес синхронізувати зі зведенням.
