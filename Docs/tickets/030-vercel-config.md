## Мета

Підготувати конфігурацію Vercel для статичної збірки, прямих маршрутів і сімейних файлів.

## Обсяг роботи

- Налаштувати build command, dist/, версію Node.js і SPA rewrites у vercel.json для карти та кімнат.
- Зберегти коректну видачу JSON, зображень, PDF та аудіо; відсутні файли не підміняти HTML сторінкою.
- Задати Cache-Control: no-store для сімейних JSON і матеріалів, не підключати service worker або офлайн-кеш.
- Підготувати окремий нешкідливий набір HTML/JSON/зображення/PDF для першої публікації; перевірити приватність репозиторію, якщо сімейні джерела використовуються у віддаленій збірці.

## Критерії приймання

- [x] Конфігурація відтворює локальну збірку та передбачає прямі /tree/I1 і /person/I1.
- [x] Існуючі файли отримують правильний тип вмісту, відсутні — 404, а не HTML зі статусом 200.
- [x] Сімейні JSON/матеріали мають заплановані no-store заголовки; постійного офлайн-кешу немає.
- [x] Пакет першої перевірки містить тільки нешкідливі приклади без родинних даних.
- [x] Вихідні GEDCOM, RootsMagic та звіти виключені з публічних ресурсів; спосіб доставки вихідних даних на збірку описаний.

## Перевірка

Перевірити результат build і правила маршрутів локально; фактичні заголовки та rewrites на Vercel перевірити в ROD-031.

## Результат і блокери

31.10.2026 завершено локальну підготовку за запитом власника:

- `vercel.json`: Other preset, Node 24.x через engines, npm 11.16.0 / npm ci,
  `npm run build:vercel` → `dist-vercel`; production не використовує стару dist/.
- `scripts/build-vercel.ts`: smoke за замовчуванням, п'ять нешкідливих файлів
  HTML/JSON/PNG/PDF/WAV, без читання Data. Явний `RODOVID_DEPLOY_MODE=family`
  збирає чинний «Сімейний атлас»; невідомий режим зупиняє збірку.
- Обмежені rewrites для семи екранів і числового personId. Немає catch-all,
  тому відсутні матеріали не отримують SPA fallback. Фактичну поведінку
  платформи й MIME ще підтверджує ROD-031; локально перевірено правила.
- Global no-store для браузера/CDN, CSP, nosniff, no-referrer, framing DENY,
  noindex, Permissions-Policy. Service worker не додавався.
- Post-build allowlist відхиляє сирі GEDCOM/RootsMagic, source maps, TS,
  звіти, symlinks і неоголошені файли; CLI upload має `.vercelignore`.
- [Інструкція Vercel](../Rodovid_Vercel_Deployment.md) містить Git privacy,
  доставку вихідних даних, env, матрицю ROD-031/032 і порядок відкату;
  [аудит](../Rodovid_Security_Audit_2026-10-31.md) описує ризики й межі.

Перевірки: типи, lint, family build (260 файлів, allowlist успішний),
smoke build (5 файлів), 16 унікальних модульних перевірок
build-vercel/static-data-plugin/load-family та 4 браузерні сценарії
Chromium desktop/Pixel 7 з CSP: карта, PNG, музика, PDF worker/сторінки/текст.
У перевіреному сценарії атласу зовнішніх запитів немає.
Браузерний конфіг — `playwright.vercel.config.ts`.

Перші запуски вперлися в sandbox localhost EACCES та тимчасовий каталог;
повтор на дозволеному localhost і `.cache/runtime` успішний.
Підсумкова папка повернена до нешкідливого smoke-режиму.
Публікації, зміни dashboard чи платних опцій не було. npm audit ще не виконано
через відсутність дозволу на передачу dependency metadata до npm Registry.
5/5 — критерії локальної конфігурації; Vercel edge authentication,
platform headers/404, membership, Git visibility і logout не зараховані
як перевірені. Їхнє приймання лишається у ROD-029/031/032.
