## Середовище

- Node.js **24.18.0 LTS** — зафіксовано в `.nvmrc`, `.node-version` та `package.json`.
- npm **11.16.0** — зафіксовано в `package.json`.
- `.npmrc` перевіряє версії середовища й зберігає точні версії нових залежностей.
- `package-lock.json` фіксує повне дерево залежностей; повторне встановлення — `npm ci`.

Перевірте `node --version` і `npm --version`. За іншої версії переключіть
Node.js через свій менеджер версій; за потреби встановіть npm командою
`npm install --global npm@11.16.0`. Системне середовище цей репозиторій не змінює.

## Локальний запуск

У Windows двічі клацніть **`start-local.bat`** у корені проєкту. Він перевірить
наявність Node.js/npm, за потреби встановить залежності, підготує дані й
відкриє сайт у браузері. Залишайте вікно запуску відкритим; зупинка — `Ctrl+C`.
За помилки вікно залишиться відкритим із поясненням. Повторний запуск при
зайнятому порту не завершує інші процеси: спершу зупиніть попереднє вікно сайту.

Обидві версії сайту використовують поточний набір
`2026-10-19-petro-birth-reviewed`. Імпорт від 19.10.2026 та подальші уточнення
описані в [актуальному реєстрі](Docs/Rodovid_Content_Status.md).
[Звіт від 12.10.2026](Docs/Rodovid_Import_2026-10-12.md) з 74 людьми —
історичний знімок попереднього імпорту.
Після наступної заміни GEDCOM потрібні реєстрація експорту й перевірка
відповідності записів у `Data/identities.json`; батнік не обходить цю перевірку.
Сайт читає `Data/Zubenko.ged`; `.rmtree` зберігається як база RootsMagic.

У терміналі в корені репозиторію:

```sh
npm ci
npm run dev
```

Відкрийте <http://127.0.0.1:5173>. Vite оновлює сторінку після змін у `src/`.
Дані й матеріали готуються при запуску. Після зміни `Data/` сервер повторно
перевіряє їх і автоматично перезавантажує сторінку з новими даними.
За помилки показує повідомлення й зберігає останній успішно перевірений набір.
Сервер прив’язаний до локального інтерфейсу. Якщо порт зайнятий, команда
завершиться з помилкою; можна явно вибрати інший: `npm run dev -- --port 5175`.
Зупинка — `Ctrl+C`.

Для перегляду готової статичної збірки:

```sh
npm run build
npm run preview
```

Відкрийте <http://127.0.0.1:4173>. Результат збірки міститься в `dist/`.
Preview потребує попередньої збірки й не перебудовує файли після редагування.
Node.js потрібний для розробки та збірки; власний API і серверна база даних
для застосунку не потрібні.

## Команди перевірки

Порядок резервування, повторного експорту зі стабільними ID, заміни матеріалів
та відновлення на окремій копії — в
[інструкції оновлення архіву](Docs/Rodovid_Archive_Update_Guide.md).

| Команда | Призначення |
| --- | --- |
| `npm run typecheck` | Строга перевірка TypeScript застосунку, конфігурацій, майбутніх скриптів і E2E-тестів. |
| `npm run lint` | ESLint для TypeScript/JavaScript, React Hooks і Fast Refresh; попередження вважаються помилками. |
| `npm run build` | Типи, свіжа конвертація й валідація, статична збірка Vite з JSON і оголошеними матеріалами. |
| `npm run data:check-gedcom` | Звірка історичного GEDCOM 02.09.2026 у `tests/fixtures/baseline-2026-09-02/`: SHA-256, рядки й посилання; звіт у `tmp/gedcom-probe.json`. Поточні дані перевіряє `data:validate`. |
| `npm run data:convert` | Перетворення й валідація → `generated/family.json`; звіти `tmp/data-conversion.json` та `.json.md`. |
| `npm run data:validate` | Повна підготовка й перевірка в пам’яті, без запису family.json/журналу ID; ті самі звіти, код 1 за помилки. |
| `npm test` | Одноразовий запуск Vitest; `src/**/*.test.{ts,tsx}` і `scripts/**/*.test.ts`, середовище Node.js. |
| `npm run test:watch` | Vitest у режимі спостереження. |
| `npm run test:e2e` | Playwright: Chromium на комп’ютері й мобільний профіль Pixel 7; окрема збірка та preview на порту 4174. |

Vitest перевіряє контракт даних, дати, налаштування, стабільні ID та парсер GEDCOM;
порожній набір більше не вважається успіхом. Інтеграційні тести перевіряють
повторну статичну збірку, матеріали й помилки входу. Playwright перевіряє
прямі адреси, історію, reload, помилки даних, мобільну навігацію,
JSON і всі оголошені локальні матеріали через preview.

Перед першими реальними E2E-тестами встановіть браузер:

```sh
npx playwright install chromium
```

Playwright не використовує вже запущений сервер, щоб перевіряти саме поточну
збірку. Порт 4174 має бути вільним. У CI заборонено `test.only`, увімкнено два
повторні запуски невдалого тесту й один worker. Деталі — у
[tests/e2e/README.md](tests/e2e/README.md).

## Структура

```text
Data/                   робочий GEDCOM, копія RootsMagic, site.json, annotations.json, identities.json
generated/              відтворюваний family.json; не редагувати вручну, не комітити
Docs/                   ТЗ, технічні рішення, огляд даних і тікети
src/
  App.tsx               маршрути, базові екрани й покажчик людей
  App.module.css        CSS Module екрана
  main.tsx              точка входу React
  data/                 Zod-схеми, типи, стабільні ID та предметні тести
  navigation/           Context, завантаження, reducer та історія перегляду
  graph/                проєкція, секторна геометрія, SVG-карта та підписи
  styles/global.css     базові стилі та CSS variables
tests/e2e/              карта, навігація та статична збірка Playwright
tests/fixtures/         окремі синтетичні приклади контракту
scripts/gedcom/         адаптер сирого GEDCOM, базова звірка й тести
scripts/check-gedcom.ts локальна команда перевірки базового експорту
scripts/convert-data.ts локальне перетворення на JSON
scripts/review-graph.ts локальні HTML/PNG для огляду геометрії ROD-010
vite.config.ts          локальні сервери та статична збірка
vitest.config.ts        окремий набір предметних тестів
playwright.config.ts    наскрізні перевірки готової збірки
```

Вихідні `Data/Zubenko.ged` і `Data/Zubenko.rmtree` не імпортуються в застосунок
і не копіюються в `dist/`; копіювання `public/` вимкнене. Плагін збірки додає
`data/family.json` і тільки оголошені файли з `Data/assets/`. JS/CSS
розміщуються в `app-assets/`; архівні оригінали зберігайте поза `Data/assets/`.
Генерований JSON не редагують вручну. Парсер працює лише в Node.js.
Залежності для карти, анімацій і медіа
додаються разом із відповідними функціями.

`node_modules/`, `dist/`, кеші, звіти, тимчасові файли й локальні `.env`
виключені з Git. Публікація та захист доступу належать до ROD-029…ROD-034;
поточна версія призначена для локальної роботи.
